# Linux BIOS 更新アプリの実装計画

対象は[一画面の基本設計](../specs/2026-11-21-linux-bios-updater-design.md)。C17・GTK 4 のクライアント、システム D-Bus サービス、権限を落とした検証プロセスを同じ Debian パッケージに収める。

| 担当 | 実装と検証 |
| --- | --- |
| 主画面 | `src/` に常設の機種・現在版と状態別の操作を実装する。模擬バスで承認前の取消、起動待ち、遅れて届く照会を確認する |
| カタログ | `backend/catalog.py` で既存の FW 検証を再利用し、署名・対象・版・ハッシュを照合する。取得した固定済み CAB を承認に結び付ける |
| 実機 | `backend/hardware.py` で DMI、ESRT、起動経路、給電、予約と試行結果を観測する。旧版・予約あり・読取不能の区別を試験する |
| 端末サービス | `backend/service.py` が要求元のセッションと接続を照合する。`backend/journal.py` に許可を先に記録し、二重承認・切断・再起動を SQLite を開き直して試験する |
| 配布 | Meson でネイティブバイナリを作成し、デスクトップエントリ、D-Bus、systemd と非特権ワーカーをパッケージ化する。ビルド、テスト、パッケージ内容を確認する |

状態の再確認はローカルの読み取りを行う。準備依頼と電源操作はそれぞれ利用者の明示操作で実行する。テストでは模擬の機器・サービスを使う。実機対応の公表は設計書の受け入れ条件に従う。
